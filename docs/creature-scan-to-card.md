# 生き物スキャンの写真を、カードにする（決定事項と未決事項）

- 作成日: 2026-10-09 ／ 最終更新: 2026-10-09
- 関連: [03_creature_scan.md](requirements/03_creature_scan.md)（スキャン機能の仕様）、[04_cards.md](requirements/04_cards.md)（カードのデータ構造）、[image-storage.md](image-storage.md)（画像の保存先と料金）

---

## 1. 大前提（決定済み）

| 項目 | 決定 | 理由 |
|---|---|---|
| 目的 | **カードとして遊ぶ**ことを最優先にする | 写真は「遊ぶためのカード」の材料 |
| 保存先 | **DBに登録する（必須）**。カードライブラリ `cards` に登録する | カードは `cards` を参照して表示・ゲームに使うため。[案A](#3-案) |
| 公開 | **登録したらすぐ使える**（`published: true`）。管理者の承認は待たない | まずは遊べる状態を優先する |
| 顔写真 | **スキャンAIで顔の写真をはじく**（カードにしない） | すぐ公開するため、人の顔を先に止める必要がある |

### この決定から出ること

- すぐ公開するので、**不適切な写真（人の顔、生き物以外）が、すぐ全員に見える**。判定で止める仕組みが必須になる。
- 持ち主（`ownerUid`）が必要なので、**スキャンにはログインが必要**になる。
- 同じ種類の生き物が、何枚も `cards` に登録される可能性がある（未決事項 Q2）。
- `cards` は誰でも書き込める状態だと困るので、**Firestore のルールを先に確認する**（未決事項 Q7）。

## 2. 現状（事実）

- **スキャン結果は保存していない。** `CreatureScan.vue` は判定結果を画面に表示するだけ。写真もどこにも残らない（要件書 5章）。
- **誰が撮ったかを、スキャン画面は知らない。** `/creature-scan` にログインのガードが無い。
- **導線は一時的に非表示。** モニタールームの「生き物スキャン」ボタンはコメントアウト中（2026-09-24〜）。
- **カードは2層。**（`src/utils/cards.js`）
  - `cards/{cardId}`：カードライブラリ。種類ごとの名前・画像・レベル・レア度・すみか・地形などを持つ。**全員で共有**。
  - `cardInstances/{instanceId}`：プレイヤーが持っている1枚ずつのカード。`cardId` で `cards` を参照し、`ownerUid` / `ownerName` / `team` / `status` を持つ。
- **画像は `cards.image` にだけある。** 表示用の `toDisplayCard()` は `card.image` を使い、「発見者」は `instance.ownerName` から出す。
- **判定APIの返す値と、`cards` の値は形式が違う。** API は `rarity.tier`・`habitat`（文字列）などを返し、`cards` は `rarity`（A〜D）・`habitat`（forest/sea/river/town/soil）・`terrain`（land/water）などを持つ。変換が要る。

## 3. 案

| 案 | 内容 | 判定 |
|---|---|---|
| **A．スキャンごとに `cards` へ登録する** | 写真を `image` にして、ライブラリに新しいカードを作る。すぐ公開 | **採用**（DB登録必須・すぐ遊べる、の要件に合う） |
| B．所持分（`cardInstances`）に写真を持たせる | ライブラリは管理された38種のまま。写真は持ち主のカードにだけ出す | 不採用（遊ぶ材料としてはライブラリに入らないため） |
| C．判定結果を `scans` に記録するだけ | カードにはしない | 不採用（カードとして遊べないため） |

## 5. 実装状況（2026-10-09）

### 作ったもの
- `src/utils/creatureCardMapping.js`：判定結果 → カードの下書き（純粋な関数。Node で動作確認済み）
- `src/utils/creatureCard.js`：写真の縮小、顔チェック、同じ学名の枚数、登録（`cards` と `cardInstances` を1つのバッチで書く）
- `src/views/CreatureScan/CreatureScan.vue`：結果の候補ごとに「これをカードにする」→ プレビュー（名前・レア度・レベル・すみか・ちいきを直せる）→ 登録
- `src/views/CardLibrary/CardLibrary.vue`（図鑑）：「📷 じぶんがとった」フィルタ、「📷 じぶん」バッジ、他の人のスキャンカードは「発見者」を表示
- `firestore.rules`・`firebase.json`：ルールの下書き（**まだ本番に反映していない**）

### 決めたこと（実装に反映）
- 登録したカードは `published: true`。`source: "scan"`、`ownerUid`、`ownerName` を付けて「誰がとったか」を残す
- 画像は 512px・WebP（使えない環境は JPEG）、上限 150KB。Canvas で描き直すので EXIF（位置情報など）は消える
- 同じ学名のカードがあっても止めない。プレビューで「もう○枚ある」と知らせるだけ
- 地域は、撮影場所のヒントに「京都」「横浜」などが入っていたら設定する（洞窟の宝箱の地域に使われる）
- 撮影場所のヒント文字は、カードには保存しない

### 圧縮サイズ（実測）
- 合成画像 4032×3024 を、512px・WebP q0.8 で圧縮した結果
  - なめらかな画像：3KB
  - 少しざらつき：18KB
  - かなりノイズが多い（最悪ケース）：74KB
- イラスト系のカード画像（既存）：7〜66KB
- **実写のスマホ写真（判定テスト用の3枚、1.5〜2MB）を同じ条件で圧縮**：512px・WebP q0.8 で 13〜14KB、q0.7 で 10〜11KB。Firestore に入れるための base64 にすると、約 17〜19KB

### 顔のチェック（未解決）
- 判定 API（ikimono-api）には顔の判定が無い。連携ガイドにもその記載は無い
- ブラウザの `FaceDetector` で調べるが、**iPhone の Safari など対応していない端末では調べられない**。その場合は「おとなが確かめました」のチェックを必須にしている
- 根本対策は API 側で顔を判定して返すこと（要相談）

### 容量の見込み（無料枠）
- 1 枚あたり、画像と情報を合わせて約 20KB。100 枚で約 2MB、450 枚（30 人 × 15 枚）で約 9MB。Firestore の無料枠（1GiB）に対して十分小さい
- 図鑑を開くたびに全カードの画像を読むため、読み込み量（無料枠は月 10GiB 程度）が増えてきたら、画像を別コレクションに分けることを検討する

### 未検証・残り
- 実際の生き物の写真で、判定 API → プレビュー → 登録の一連の流れを確かめていない（写真が未提供）
- Firestore ルールは未デプロイ。エミュレータでの検証もしていない
- 判定 API の返却データは、テスト用に保存して使いまわす予定（写真を受け取り次第）
