# 端末の統計（どんな画面で使われているか）

- 作成日: 2026-10-03
- 目的: どんな端末・画面の大きさで使われているかを知って、画面の作りの優先順位を決める
- 方針: **個人を特定しない、粗い分類だけを、回数として数える**。外部の解析サービスには送らない

---

## 1. 集めるもの・集めないもの

| 集める | 中身 |
|---|---|
| 端末の種類 | スマホ / タブレット / PC（「指で操作する端末か」と、画面の短い辺が600px未満かで判定） |
| 画面の幅の区分 | 〜359 / 360〜399 / 400〜599 / 600〜1023 / 1024〜（正確なピクセル数は見ない） |
| OS の名前 | iOS / Android / Windows / Mac / その他（バージョンや型番は見ない） |
| 使い方 | ホーム画面アプリ（PWA）か、ブラウザか |

| **集めない** |
|---|
| IPアドレス ／ ブラウザの情報の全文（UAの全文） ／ 正確な画面サイズ ／ 端末の個別ID ／ 名前や `cenId` との紐づけ |

これらは、組み合わせると個人を特定できてしまう可能性があるため、集めない。

## 2. 送り方

- **1つの端末が、1日に1回だけ**、モニタールームを開いたときに送る（`localStorage` の `deviceStatsSentDate` に、送った日（日本時間）を覚えておく）
- 送る先は、このアプリの Firestore の **`deviceStats/{日付}`** だけ。**数字を足す**だけで、1人ずつの記録は作らない
  - 例：`deviceStats/2026-10-03` → `{ date, total: 15, counts: { "phone__w400-599__ios__app": 9, "pc__w1024up__windows__web": 6 } }`
  - キーの形：`{端末の種類}__{幅の区分}__{OS}__{app|web}`
- **ce-n.org（Wix）・ハブサイト・Google Analytics などの外部サービスには、送らない**
- 開発用の環境（`localhost`・同じWi-Fi内のIP。画面に `(DEMO)` が出る環境）では、送らない
- 送るのに失敗しても、アプリの動きには影響しない（エラーを記録するだけ）

## 3. 集計の見方

- モニタールームの仮リンク「端末の集計を見る（仮）」（`/device-stats`）で見られる
- Firestore には「日付ごとの回数」しか入っていないので、**画面側で足し直して**、種類ごと・幅ごと・OSごと・使い方ごとの割合（棒グラフ）と、日ごとの回数を出す（直近90日）
- 「1回」は、「1つの端末が1日にあそんだ」の意味。**人数ではなく、回数**

## 4. お知らせ

モニタールームの画面に、小さく「どんな画面で あそばれているか、回数だけを かぞえています。名前や ID は つかいません。」と表示している。

## 5. 注意点・これから

- Firestore のセキュリティルールが開いているため、**この数字は、誰でも読めて、書き換えられる**（中身は回数だけで、個人情報は入っていない）。統計は「おおよその傾向を見る」ものとして使う。本番の前に、ルールを整える
- 子ども向けの企画なので、運営側（子ども環境ネットワーク）の個人情報・プライバシーの方針と、合っているかの確認が必要（外部に送らない・個人と結びつけない、という作りにしてある）
- 管理者用の画面（`/device-stats`）は、いまは誰でも開ける仮画面。本番前に、管理者だけにする
