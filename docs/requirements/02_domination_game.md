# 陣取りゲーム（DominationGame）要件定義書

- 対象: `DominationMap.vue` / `DominationGame.vue`（`src/views/DominationGame/`）
- 作成日: 2026-09-19
- 位置づけ: [00_overview.md](00_overview.md) の詳細版（陣取りゲーム部分）。実装済みの仕様をベースに記載

---

## 1. 概要・目的

3チーム（水・空気・土）が、北海道の生きものカードをフィールドのマス目に配置して縄張りを取り合うターン制ボードゲーム。モニタールームの「野生にもどそう！」から入る。

- 1台の端末を囲んで複数人（または1人＋AI）で遊ぶ「ホットシート」形式。ネットワーク越しの対戦ではない。
- チーム分けはログイン時に割り当てられた `myTeam`（water/earth/air）を踏襲する。

## 2. 画面構成・画面遷移

| 画面 | ルート | 役割 |
|---|---|---|
| DominationMap | `/dominationMap` | 導入演出。Leafletの地図で平塚市・釧路市を紹介するカットシーン |
| DominationGame | `/dominationGame` | ゲーム本編 |

- MonitorRoom「野生にもどそう！」→ DominationMap（演出後、自動でDominationGameへ遷移）
- DominationGame「戻る」→ MonitorRoom（`{ name: 'Home' }`。以前は存在しないルート名`MonitorRoom`を指していて機能していなかったバグを2026-09-19に修正）

## 3. プレイヤー構成

| id | チーム | 色 |
|---|---|---|
| 1 | 水チーム | `#00BFA6` |
| 2 | 空気チーム | `#9B5DE5` |
| 3 | 土チーム | `#FFB97A` |

- **人間が操作するのは自分のチーム（`localStorage.myTeam`）1チームのみ**。残り2チームは自動的にAIが操作する（`myTeam`未設定時は水チームが人間扱い）。
- ヘッダーのチームバッジに🤖アイコンでAI操作かどうかを表示。

### AIロジック（シンプルなランダムAI）
1. 手番がAIチームになると「🤖 ◯◯チームが考え中…」バナーを表示し、0.9〜1.4秒待つ（考えている演出）。
2. 手札をシャッフルし、先頭から順に「配置できるマスが1つでもあるカード」を探す。
3. 見つかったら、そのカードが置けるマスの中からランダムに1つ選んで配置。
4. どのカードも置ける場所が無ければスキップ扱いにする。
5. 配置/スキップ後、次のプレイヤーへ。次のプレイヤーもAIなら自動的に連続して手番を進める（人間の番になったら止まる）。
6. AIの手番中は盤面クリック・カード選択・スキップボタンを無効化する。

## 4. 盤面（フィールド）

- 30列 × 15行 = 450マスのグリッド。`generateTiles()` で毎回ランダム生成。
- 地形の種類: `town`（町）/ `forest`（森）/ `dirt`（土）/ `river`（川）/ `sea`（海）/ `undeveloped`（未開発地）。
  - 海・川はシード地点から不規則に拡張生成（`makeOcean` / `makeRivers`）。
  - 町・森・土地は複数のシードから隣接タイルへ確率的に拡張。
  - 残りのマスの一部（約1/8）が「未開発地」になり、カードを配置できない。

## 5. カード・デッキ

- `allCards` に約36種類のカードを定義（北海道の実在の生き物）。各カードは以下を持つ:
  - `area`: `land`（陸地）/ `water`（水辺）— 置けるマスの地形を決める
  - `tier`: 1〜4（レベル）
  - `count`: デッキ内の枚数
- `buildDeck()` でカード定義から実際の山札（枚数分に展開、`instanceId`付き）を構築し、シャッフルして3チームに均等配布。

### 配置ルール
- `area` が `water` のカードは `river` / `sea` のマスにのみ、`land` のカードはそれ以外（`undeveloped`除く）のマスにのみ置ける。
- Lv1は無条件でどこでも置ける（対象地形であれば）。
- Lv2以上は、**隣接8マス（斜め含む）に、自分より1段階下のtierのカードが2枚以上（まだ「食われていない」もの限定）** 置かれている必要がある（食物連鎖を積み上げていく設計）。
- 既にオーナーがいるマス、未開発地には置けない。

### 「食べる」処理
- カードを配置すると、隣接マスに置かれている**自分より低いtierのカード**は「食われた」扱いになり（`eatenByTileId` / `eatenByPlayerId`）、盤面の色が食べた側のチームカラーに変わる。
- 食われたカードは、以後の「隣接2枚チェック」の対象から除外される。

### スコア
| tier | 得点 |
|---|---|
| 1 | 1点 |
| 2 | 3点 |
| 3 | 5点 |
| 4 | 8点 |

配置した瞬間に、配置したプレイヤーのスコアに加算される（食われた側から減点等は無い）。

## 6. ターン進行・終了条件

- 3チームで順番に手番が回る（`goToNextPlayer`）。
- 「スキップ」: 確認ダイアログ後、次のプレイヤーへ。全員が連続でスキップしたら自動終了。
- 「ゲーム終了」: 確認ダイアログ後、即座に終了（手動終了）。
- 全プレイヤーの手札が0枚になったら自動終了。
- 終了時、スコア降順の一覧をモーダル表示し、「もう一回遊ぶ」で同じルームのまま新しい盤面・手札・スコア0でやり直せる。

## 7. データ永続化（Firestore）

- 保存先: `dominationGames/{ルームコード}`（1ルーム＝1ドキュメント）。
- 保存タイミング: カード配置時／スキップ時／ゲーム終了時／新規マップ再開時／AIの手番完了時。
- 保存内容: `tiles`（450マスの状態）、`hands`（3チーム分の手札）、`players`（id・スコア）、`currentPlayerId`、`skipCount`、`gameState`、`updatedAt`。
- 起動時（`mounted`）に該当ルームコードの保存データがあれば読み込んで再開し、無ければ新規に盤面・手札を生成して保存する。
- `isAI`（どのチームをAIにするか）は保存/復元の対象外。**毎回そのデバイスを開いた人の`myTeam`から都度算出する**（別の人が同じルームを別デバイスで開いた場合、その人のチームが人間扱いになる）。

### ルームコード
- 陣取りゲームは元々「共有の1ゲーム」を前提にしていたが、**複数のグループが同時に別々のゲームを遊べるように「ルームコード」を導入**（2026-09-19）。
- 初回アクセス時に4文字のコード（例: `U5PW`。`0/O`, `1/I/L`等紛らわしい文字は除外）をランダム生成し、`localStorage.dominationRoomCode` に保存。以後そのデバイスは同じルームを使い続ける。
- 画面左上にルームコードを表示（クリックでクリップボードにコピー）。
- 「ルームを変える」から別のコードを入力して他のルームに参加可能。存在しないコードを入力した場合は、そのコードで新しいルームが作られる。
- 現状、ルームコードを他者に伝える手段はアプリ内には無く、口頭やメモでの共有を想定している。

## 8. UI構成（2026-09-19 大幅刷新）

- **ヘッダー**: タイトル、ルームコード表示・変更、3チームのスコアバッジ（現在の手番をハイライト、AIチームは🤖表示）
- **AI思考中バナー**: AIの手番中、画面上部に「🤖 ◯◯チームが考え中…」を表示
- **盤面**: 画面幅いっぱいを使った大きめのタイルグリッド。配置済みのアイコン（▲Lv1/■Lv2/●Lv3/★Lv4）には黒フチを付けて地形色に埋もれないようにしている
- **サイドバー**: 地形・レベルの凡例（折りたたみ式）、現在の手番プレイヤーの手札（tier別グループ表示。AIの手番中は手札を隠し「考えています…」を表示）、操作ボタン（キャンセル／スキップ／ゲーム終了／戻る／新規マップで再開）
- **モーダル**: カード選択時のプレビュー、盤面のカードをクリックした際のプレビュー、ゲーム終了時のスコア一覧

## 9. 既知の課題・未実装

| 項目 | 内容 |
|---|---|
| `mapControl` モード | `changeMode()` や地図画像を使った代替UIが残っているが、呼び出し経路が無く実質デッドコード |
| ルームコードの共有手段 | コードをコピーする機能はあるが、送る相手に伝える導線（QRコード化・URL化等）はアプリ内に無い |
| 同時書き込みの競合 | 同じルームコードを複数端末で同時に開いた場合、Firestoreへの書き込みが競合する可能性がある（想定利用は1ルーム=1端末） |
| AIの強さ | 完全ランダム配置で、食物連鎖の積み上げ戦略やスコア最大化などは考慮していない（「簡単なアクション」という要望に沿ったシンプル実装） |
| `getDisplayHand` / `makeTowns` / `highestPlayerScore` 等 | 定義されているが実際には使われていないメソッドが残っている |
