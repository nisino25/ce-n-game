# 生きものカード（カードDB）要件定義書

- 対象: カードのマスタデータ・所持カードのFirestore設計と、洞窟探検（`CaveEnd.vue`）・陣取りゲーム（`DominationGame.vue`）での扱い
- 作成日: 2026-09-26
- 位置づけ: [00_overview.md](00_overview.md) の「カード収集・所持データ（`collection`）のFirestore移行」にあたる詳細版。**まだ実装前の設計段階**
- ステータス: 一部実装済み（2026-09-26）。カードライブラリ・所持カード・宝箱・カードライブラリ画面・野生にもどそう！の枚数制限・陣取りゲームの山札と配置まで

---

## 1. 概要・目的

洞窟探検で集めた「生きものカード」を、そのまま陣取りゲームで使えるようにする。そのために、現在バラバラに定義されているカード情報をFirestoreの1か所にまとめ、プレイヤーが持っている1枚1枚のカードの状態（手元にある／どの陣取りゲームの盤面に置かれているか）を管理できるようにする。

## 2. 現状（2026-09-26時点）

カード情報は3か所にハードコードされており、形式もそろっていない。

| 場所 | 内容 | 形式 |
|---|---|---|
| 洞窟探検の宝箱（`CaveEnd.vue`） | ウサギ・アカウミガメの2枚 | `name, icon, level（画像パス）, rare, area1, area2（画像パス）, group（土/水/風）, card（silver）` |
| 陣取りゲーム（`DominationGame.vue` の `allCards`） | 北海道の生きもの37種 | `id（和名）, area（land/water）, food, tier（1〜4）, count` |
| shineki-game のカード登録画面（`cardCollection.vue`） | サンプル3枚 | `id, label, area, location, level, imgSrc`（別のFirebaseプロジェクト） |

- 獲得したカードは `localStorage` の `collection` にカード情報を丸ごとコピーして保存しているだけ。端末を変えると消え、ログアウトしても消えない。
- `users/{uid}.cards[]` というフィールドはあるが、どこからも書き込まれていない。
- 同じ「生態系レベル」が、洞窟側は画像パス、陣取り側は `tier` と別々に表現されていて、2つのゲームがつながっていない。

## 3. 決定事項

| 項目 | 決定内容 |
|---|---|
| 陣取りゲームの山札 | **洞窟探検で集めたプレイヤーのカードを使う**（固定デッキは使わない） |
| 陣取りゲームで使ったカード | **盤面に置いたカードは、その盤面にそのまま残り続ける**（手元には戻らない）。手札に残って置かなかったカードは手元のまま |
| カードの持ち主 | **個人**。モニタールームの「チーム保有カード」はチームメンバーの合計で表示。陣取りではチーム全員分のカードを使う |
| 土・水・風（チームカラー） | **カードを取得したプレイヤーのチーム**。生きものの種類ではなく、所持カード1枚ごとに持つ |
| 野生にもどそう！の条件 | **手元のカード（`status: "collection"`）が10枚以上ないと遊べない**。足りないときはモニタールームで「カードが足りません（いま◯枚）」を表示 |
| カードライブラリ画面 | `/card-library`。DBに登録されている全カードと、自分が何枚持っているか（手元／盤面）を表示。今はモニタールームの仮リンクから入る |

## 4. データ構成（Firestore）

「カードの種類（マスタ）」と「プレイヤーが持っている1枚1枚のカード（所持カード）」を分ける。

### 4-1. `cards/{cardId}` — カードマスタ（生きものの種類ごとに1件）

| フィールド | 型 | 例 | 用途 |
|---|---|---|---|
| `cardId` | string | `"higuma"` | ドキュメントID と同じ。ローマ字の英小文字で付ける |
| `name` | string | `"ヒグマ"` | カードの名前 |
| `image` | string | `"/images/card/ikimono/higuma.png"` | 生きものの画像 |
| `level` | number | `4` | 1〜4。カードの「生態系レベル」表示と、陣取りゲームの `tier` を**この1つに統一** |
| `terrain` | string | `"land"` | `land` / `water`。陣取りゲームで置けるマスの地形 |
| `food` | string[] | `["植物", "小動物"]` | 食べるもの（陣取りゲームのカード表示用） |
| `habitat` | string | `"forest"` | すみか。`forest` / `sea` / `river` / `town` / `soil`。カードのすみかアイコン |
| `region` | string | `"hokkaido"` | `hokkaido` / `kanagawa` / `kyoto`。どのエリアの洞窟の宝箱から出るか |
| `rarity` | string | `"A"` | レア度（A〜D）。カード表示と宝箱からの出やすさ |
| `frame` | string | `"silver"` | `silver` / `gold`。カードの枠 |
| `published` | boolean | `true` | `false` の間はゲームに出さない（準備中のカードを登録しておける） |
| `createdAt` / `updatedAt` | timestamp | | |

- レベルアイコン・すみかアイコンの**画像パスはDBに持たない**。`level` / `habitat` からコード側で組み立てる（画像の差し替えに強くするため）。
- 陣取りゲームの `count`（固定デッキの枚数）は、山札をプレイヤーのカードで作ることになったため**持たない**。

### 4-2. `cardInstances/{instanceId}` — 所持カード（プレイヤーが持っている1枚ごとに1件）

| フィールド | 型 | 例 | 用途 |
|---|---|---|---|
| `cardId` | string | `"higuma"` | どのカードか（`cards` への参照） |
| `ownerUid` | string | `"1790250650104"` | 持ち主（`users/{uid}`） |
| `ownerName` | string | `"れお"` | カードの「発見者」表示用（取得時点の名前） |
| `team` | string | `"earth"` | 取得したプレイヤーのチーム（`water` / `earth` / `air`）。カードの土・水・風の色 |
| `obtainedAt` | timestamp | | 取得日時 |
| `obtainedFrom` | string | `"cave:hokkaido"` | 取得元（洞窟のエリアなど。将来ほかの入手方法が増えても区別できるように） |
| `status` | string | `"collection"` | 状態（4-3参照） |
| `dominationRoomCode` | string \| null | `"U5PW"` | **どの陣取りゲームの盤面に置かれているか**（置かれていなければ `null`） |
| `tileId` | number \| null | `128` | 置かれているマス |
| `placedAt` | timestamp \| null | | 置いた日時 |
| `eatenAt` / `eatenByInstanceId` | timestamp / string \| null | | 盤面で食べられた日時と、食べたカード |
| `statusUpdatedAt` | timestamp | | 状態を変えた日時 |

- `localStorage` の `collection` と、使われていない `users/{uid}.cards[]` はこれに置き換える。
- 1人が同じ生きものを何枚持っていてもよい（1枚ごとに別の `instanceId`）。

### 4-3. 所持カードの状態（`status`）

| status | 意味 | 陣取りの手札に入るか |
|---|---|---|
| `collection` | 手元にある（未使用） | 入る |
| `placed` | 陣取りゲームの盤面に置かれている。そのまま残り続ける | 入らない |
| `eaten` | 盤面に置かれた後、ほかのカードに食べられた。盤面には残る | 入らない |

```
collection ──（陣取りで盤面に置く）──▶ placed ──（上位のカードに食べられる）──▶ eaten
```

- 一度 `placed` になったカードは手元（`collection`）には戻らない。
- 「どのカードがどの陣取りゲームで使われているか」は `status` + `dominationRoomCode` + `tileId` で分かる。

## 5. 各ゲームでの扱い

### 5-1. 洞窟探検（宝箱）

1. 宝箱を開けると、そのエリア（`region`）の `published: true` のカードから、`rarity` に応じた確率で1枚選ぶ。
2. `cardInstances` に `status: "collection"` で1件作る（`ownerUid` / `ownerName` / `team` はログイン中のプレイヤー）。
3. 「獲得カード一覧」は、自分の `cardInstances` を `cards` と組み合わせて表示する。

### 5-2. 陣取りゲーム

1. チームの手札 = そのチームのメンバー全員の `status: "collection"` の所持カード。
2. カードを盤面に置いたら、その所持カードを `status: "placed"`・`dominationRoomCode`・`tileId`・`placedAt` に更新する。
   - 同じカードが別のゲームで同時に置かれないように、**Firestoreのトランザクションで「まだ `collection` であること」を確かめてから更新**する。
3. 置いたカードがほかのカードを食べたら、食べられた側を `status: "eaten"` に更新する。
4. 配置できるかの判定は今のルールのまま（`terrain` で地形、`level` で「1段階下のカードが隣に2枚以上」）。

### 5-3. モニタールーム

- 個人保有カード: 自分の `status: "collection"` の枚数（盤面に置いたものを含めるかは未決定。6章参照）。
- チーム保有カード: チームメンバーの合計。

## 6. 未決定事項

| # | 項目 | 論点 |
|---|---|---|
| 1 | AIのチームの山札 | AIのチームにはプレイヤーがいないのでカードが無い。**今は仮に、カードライブラリから人間チームと同じ枚数を引いた仮のカードにしている**（7章）。これでよいか |
| 2 | カードが少ないチーム | カードが0枚・少ないチームは陣取りで何もできない。最低限の基本カードを配るか、そのまま（集めたチームが有利）にするか |
| 3 | 「新規マップで再開」 | 盤面のカードは「残り続ける」ことになったが、マップを作り直すとき、その盤面に置かれていたカードはどうなるか（消える／記録として残る／手元に戻る） |
| 4 | 手札に入れるカード | 手元のカードを全部手札にするか、プレイヤーが持っていくカードを選ぶか |
| 5 | 宝箱の確率 | `rarity` ごとの出やすさ（例: A 5% / B 15% / C 30% / D 50%）と、`frame`（silver/gold）の決め方 |
| 6 | 保有カードの数え方 | モニタールームの「保有カード」に、盤面に置いたカード（`placed` / `eaten`）も含めるか |
| 7 | カードの一覧 | 最終的なカードのリスト（名前・画像・レベル・地形・すみか・エリア）はどこから用意するか（スプレッドシート等）。現状、画像があるのはウサギ・アカウミガメの2枚のみ |
| 8 | カードの登録方法 | マスタの追加・編集を、管理画面（shineki-game のカード登録画面を流用？）でやるか、スクリプトで一括登録するか |
| 9 | 既存データの移行 | `localStorage` の `collection` に残っているカードを引き継ぐか（テスト段階なので引き継がない案） |

## 7. 実装状況

| 作業 | 状況 |
|---|---|
| カードマスタ（`cards`）の登録 | 済（38種）。陣取りゲームの `allCards` 36種（重複のモンシロチョウを除く）＋洞窟のウサギ・アカウミガメ。**レア度はレベルから（Lv4=A〜Lv1=D）、すみかは地形から（水辺=川・陸=森）仮に設定**。画像はウサギ・アカウミガメのみ |
| 洞窟探検の宝箱を `cards` / `cardInstances` に切り替え | 済。そのエリアのカードからレア度の重み（仮: A5/B15/C30/D50）で抽選。エリアのカードが無い場合（今は京都）は全カードから。保存に失敗したらカギを返す |
| 宝箱画面の「獲得カード一覧」 | 済。自分の `cardInstances` から表示。「カードクリア（仮）」は自分の所持カードをDBから削除する |
| モニタールームの保有カード数 | 済。個人＝自分の手元のカード、チーム＝チームの手元のカードの合計（以前は個人×9の仮の値） |
| カードライブラリ画面 | 済（`src/views/CardLibrary/CardLibrary.vue`） |
| 野生にもどそう！の10枚制限 | 済（モニタールームのボタン。仮リンクの「陣取りゲームに直接アクセス（仮）」は制限なし） |
| 陣取りゲームの山札・配置を `cardInstances` に切り替え | 済。人間チームの手札＝チームメンバー全員の `collection` のカード（保存済みのルームを開いたときもDBから作り直す）。置くとトランザクションで `placed`（ルームコード・マス）に、食べられると `eaten` に更新。固定デッキ `allCards` は削除 |
| AIチームの山札 | **仮対応**。カードライブラリからレベルの重み（Lv1:4 / Lv2:3 / Lv3:2 / Lv4:1）で、人間チームの手札と同じ枚数（最低10枚）を引いた仮のカード。所持カードではないのでDBは更新しない（6章 #1 が決まったら見直す） |

| Firestoreのセキュリティルール | 未（今はクライアントから自由に書き込める） |
